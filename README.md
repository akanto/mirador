# Mirador

A localhost web app that drives coding agents (Claude Code and opencode today; pi next) over ACP and gives them a **canvas**: a browser panel where they render HTML, diagrams, mockups and 3D scenes (`show`), and ask you to choose between options with visual previews (`ask`).

## Run

```bash
bun install
bun start
```

Open the `http://127.0.0.1:4600/auth?token=…` link the host prints (once per browser; it sets a cookie). Stop with Ctrl+C, which also stops the agent processes.

Runs on macOS and Linux (x64 and arm64). [`desktop/`](desktop/README.md) wraps it in a menu bar / tray app with its own window on both.

- **Workspaces** are project directories (sidebar `+`; Tab completes paths), each a card in the sidebar with its conversations oldest first, so a new one appears at the bottom, next to *+ New*. The chip beside *+ New* chooses the agent (Claude Code, opencode, or a profile, which belongs to one of them); each workspace remembers it. Agents run in that directory with your normal settings: Claude Code with `~/.claude` (settings, hooks, MCP servers; claude-notifier is muted for app sessions), opencode with `~/.config/opencode` (providers, agents, plugins, MCP servers, **and its permission settings**: the app forces nothing, so with opencode's defaults most tools run without asking). Approvals the agent asks for appear in the browser.
- **opencode** is found on `PATH`, else in `/opt/homebrew/bin`, `/usr/local/bin` or `~/.opencode/bin`. The chat header lists all its models and modes (build, plan, your agents).
- **Profiles** (sidebar, *Profiles…*): an agent plus the environment it starts with, e.g. Claude Code through a work gateway or a local llama.cpp server, or opencode with another config (`OPENCODE_CONFIG=…` or inline `OPENCODE_CONFIG_CONTENT='{…}'`). A profile's agent is fixed once created. Environment lines are `KEY=value`, `-u KEY` and `# comment`, so the lines of an existing `claude_env=( … )` alias paste as they are; an optional pre-launch command (your shell) can start a proxy first. Each profile runs its own agent process; its log is `logs/<agent>-<name>-<id>.log`. A conversation can move to another profile of its agent (*Profile* at the top of the conversation, also after its profile was deleted): the new profile's agent process resumes the same session, with that profile's model. Switching while the agent works stops the turn, and once the session is back the agent is asked to continue where it left off (queued messages follow). If the profile keeps sessions elsewhere (another `CLAUDE_CONFIG_DIR`, or opencode's `XDG_DATA_HOME`), the session cannot be resumed and a fresh one starts. Profiles, including their tokens, are stored in the app's SQLite database in the data directory (owner-only permissions).
- **Continue…** (in each workspace's card) lists the sessions the workspace's chosen agent recorded for that directory, including ones started in a terminal, and replays the chosen one into a new conversation. *Continue* keeps the same session (close it in the terminal first: nothing stops two writers); *Fork* copies it. While a Claude Code session is still open in a terminal, its conversation says so (header badge, sidebar dot, a note above the message box) along with what it is doing there: working, waiting for you, or idle. The app reads this from Claude Code's session registry (`~/.claude/sessions`, or the profile's `CLAUDE_CONFIG_DIR`); it does not show the terminal's new messages. opencode has no such registry.
- **Keyboard**: `⌘K` opens a palette (go to any conversation; new conversation, continue a session, profiles, add workspace, canvas). `⌥↑/⌥↓` previous/next conversation, `⌥⇧↑/⌥⇧↓` previous/next workspace, `⌥1…⌥9` the n-th conversation of the current workspace, `⌥T` new conversation in it, `⌘\` shows/hides the canvas, `⌘⇧←/⌘⇧→` focus the message box / the canvas, `?` lists them all (Ctrl instead of ⌘ off macOS). They work while a canvas page has focus too, except `⌥T`: a page the agent wrote cannot start conversations. The ⌥ bindings go by physical key, so they also work on layouts where ⌥ types characters, but they then shadow those characters in the app (e.g. ⌥1…9 on the Hungarian layout).
- **Renaming**: click a conversation's title in the chat header, double-click it in the sidebar, or use *Rename conversation…* in the palette (Enter saves, Esc cancels). A name you choose sticks; otherwise the title is your first message until the agent names the session (Claude Code does after the first turn).
- **Terminal** (the Terminals pane): `⌘K` clears it on macOS. On Linux, `Ctrl+Shift+C` copies the selection and `Ctrl+Shift+V` pastes, as in a Linux terminal; `Ctrl+C` stays the interrupt.
- **Typing** (macOS, *Settings…*): spelling autocorrection and inline word predictions are off by default in the app's text fields; each can be switched on. The terminal never gets them.
- **Theme** (*Settings…*): Light (the default, whatever the system uses), Dark, or Match system; remembered per browser.
- **YOLO** (top of a conversation, off by default): the app approves every permission request of that conversation without asking (allow once; switching it on also approves requests already waiting). Works the same for Claude Code and opencode. Claude Code's own *Bypass permissions* mode, in its *Mode* list, is separate.
- **Timestamps**: lines are grouped by author, and each group's header shows who wrote it and when. Point at a later line in the group to see its time (hover the time for the full date); *Show timestamps* in *Settings…* shows them on every line. Remembered per browser. History loaded from a session started elsewhere carries the time it was loaded, not when it was written.
- **Questions** (chat header): *Agent waits for my answer* returns your choice as the `ask` tool result. *My answer is sent as the next message* lets the agent end its turn, and your choice arrives as your next message.
- **Notifications**: a question, a permission request, a finished turn or an error brings a system notification, unless that conversation is on screen in a focused window. In a browser, switch them on in *Settings…* (the browser asks for permission once); clicking one opens the conversation. The [desktop app](desktop/README.md) shows them natively instead, also while its window is closed, and browser tabs on that computer stay quiet meanwhile so nothing arrives twice; other devices joined to it still get their own.
- **Waiting for you**: the sidebar marks each conversation whose agent waits for you: *Needs you* while a permission request or a canvas question is unanswered, *Done* (or *Failed*, after an error) when a turn ended while you looked elsewhere, until you open it. *Waiting for you* in *Settings…* picks the look: a pill on the row and a count on the workspace (the default), only a coloured dot and a bold title, or the pills plus a list of every waiting conversation above the workspaces. Every window shows the same marks, and they are kept across host restarts.
- **Messages from scripts**: a job the agent leaves running can tell it when it is done. [`scripts/mirador-message`](scripts/mirador-message) `"<text>"` (or text on stdin) sends the text to the agent's conversation as your next message: at once if the agent is idle, else queued like one you typed. It shows as *From a script*. It finds the conversation by Claude Code's `CLAUDE_CODE_SESSION_ID`, which every command the agent runs inherits, along with the `MIRADOR_URL` and `MIRADOR_SCRIPT_TOKEN` the host gives its agents; anything else needs `--session <agent session id>`. opencode gives its commands no session id, so its conversations can only be reached with `--session`. The script token stays the same across host restarts, so a job still waiting through a restart gets through.
- **Jobs left running**: instead of polling a job it started in the background, the agent runs `mirador when-done --pid <pid> "<message>"` (or `--container <name>` for a Docker or Podman container, and `--host <user@host>` for a job on another machine, reached over ssh) and ends its turn. The host checks on the job (a process every second, a container every 5 seconds, another machine every 20 seconds) and, when it ends, sends the message as your next message (*From a script*), so the agent carries on; with `--no-resume` only you get a notification. Without a message it says which job ended. Over ssh only a check that sees the job gone ends the wait; after 30 failed checks in a row (10 minutes) the host gives up and says the job may still run. While it waits, the conversation shows the job above the message box, with *Stop waiting*. Waits are kept in the database, so they go on after a host restart, and a job that ended meanwhile is noticed then. Mirador puts its `bin` folder at the end of its agents' `PATH` and tells Claude Code about the command in its system prompt; opencode gives its commands no session id, so it needs `--session <agent session id>`.
- **Working on Mirador in Mirador**: the host watches its own source. `⌘R` reloads the page with the UI code as it is now (the host rebuilds the bundle when `web/` or `shared/` changes; in the desktop window too, which has no reload menu item). When `host/` or `shared/` changed since the host started, a banner above the conversation offers a restart; `⌘⇧R` (or *Restart the host* in the palette) restarts it in place: it stops working agents' turns the way Stop does, re-executes itself in the same process (so the desktop app, launchd or your terminal keeps seeing the same host), and then asks those agents to continue where they left off. Terminal shells start over. Messages queued for an agent are kept in the database, so they also survive a host stopped any other way (the tray's *Restart host*, a crash): they go out once the host is back. Open pages reload by themselves whenever the host restarted, however it was restarted. In a Linux terminal pane, `Ctrl+R` stays the shell's history search.
- State lives in `~/.mirador` (SQLite, browser and script tokens, agent logs under `logs/`).

Environment: `MIRADOR_PORT` (default 4600; canvas assets use the next port), `MIRADOR_DATA_DIR`. `bun run dev` enables hot reload of the UI (only for working on `web/`; open pages swap code mid-session).

## Develop

```bash
bun run typecheck
bun test tests          # unit tests
bunx playwright test    # e2e: a real Claude Code on haiku, opencode against a scripted fake model (installed Google Chrome on macOS, Playwright's Chromium elsewhere)
MIRADOR_E2E_MINIMAL_ENV=1 bunx playwright test e2e/agent-flow.spec.ts   # host started with a bare environment
MIRADOR_EXPERIMENT=1 MIRADOR_TEST_MODEL=default MIRADOR_TEST_EFFORT=default bunx playwright test e2e/experiment-unprompted.spec.ts
```

On Linux, from any machine with Docker (`MIRADOR_LINUX_ARCH=x64` or `arm64`, default this machine's; the other one runs emulated and slowly):

```bash
scripts/linux-test.sh      # type check, unit and e2e tests in Ubuntu 24.04; export ANTHROPIC_API_KEY for the tests that need a real Claude reply
scripts/linux-desktop.sh   # builds the desktop app's installer, installs it and checks it starts, opens at login and stays single-instance
```

Layout: `host/` (Bun server, ACP client, canvas MCP server, SQLite store), `web/` (React UI bundled by Bun), `shared/` (types and the canvas document builder), `spike/` (throwaway feasibility spike, see `spike/FINDINGS.md`). Work is tracked in beads (`bd ready`).
